# Use-case cards

Twelve cards from the first study. Each is a moment where a UI would beat chat. The interview asks about a card only when its Gate fires in this person's `session_miner_report.md`; cards with a zero gate are marked "not asked" and rank by evidence alone. A gate whose metric is `not measured` for every harness present does not fire; write "not asked (not measured)".

Metric names in the Gate column are the report's own tables: Agent dispatches; Tracking and hand-off tools; MCP servers (calls, drafts, sends); "What the human turns ask for", where an ask category count is primary plus "also matched" (`aggregates.asks_all` in the JSON, one turn can hit several categories); Agent behaviors; Feedback signals and Feedback batches; Steering (resumptions); Write/Edit by file extension; Bash commands (process probes and waits); Session inventory; By hour of day.

| # | Use-case | Trigger (behavior) | Shows (components) | You can (interactions) | Evidence metric | Gate |
|---|---|---|---|---|---|---|
| 1 | Live run board | Two or more subagents dispatched, or a plan with 3+ items | Plan items by wave with state (queued, implementing, in review, fix round n, done, blocked); agent roster with elapsed time and files owned; CI state; last update stamp | Collapse, reorder, skip, ask for detail on one item, message one agent, cancel a lane | Agent calls, parallel fan-outs, "status or steering" ask turns, TaskCreate | Agent calls > 0, or "status or steering" ask turns > 0, or TaskCreate > 0 |
| 2 | Needs-you panel with one-click unblocks | The agent hits a human-only step (approve or merge a PR, register a redirect URI, unlock the machine, provide a key) | Each blocker with why, what it unblocks, exactly one control; secrets go into a masked field, never the composer | Done, paste securely, defer, ask the agent to do it itself | Blocked on user (agent behaviors), "unblock or manual step" ask turns, PushNotification calls, secret-shaped strings | blocked on user > 0, or "unblock or manual step" ask turns > 0, or PushNotification > 0, or secret-shaped strings > 0 |
| 3 | Verification board | The agent claims done | Per item: merged, CI, deployed, tagged, updated on device, data landed, each with a live probe or linked artifact | Re-run a probe, expand evidence, accept | Done claims, done claims followed by a trust probe, "trust check" ask turns | done claims followed by a trust probe > 0, or "trust check" ask turns > 0, or "review or verify" ask turns > 0 |
